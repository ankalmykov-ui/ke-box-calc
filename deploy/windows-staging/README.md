# Временный staging на Windows

Этот контур запускает PostgreSQL 17 и backend KE | BOX CALC v2 на одном постоянно включённом Windows-компьютере. Схема данных и миграции остаются переносимыми: позднее базу можно перенести через `pg_dump`/`pg_restore` без переделки приложения.

## Требования

- Windows 10/11 x64;
- Docker Desktop с автоматическим запуском после входа;
- включённая аппаратная виртуализация;
- постоянное питание и желательно ИБП;
- свободное место для базы и резервных копий.

## Первый запуск

1. Скопируйте `.env.example` в `.env`.
2. Замените `POSTGRES_PASSWORD` длинной случайной строкой из латинских букв и цифр. Не используйте `@`, `:`, `/` и другие символы, требующие URL-кодирования.
3. В PowerShell из этой папки выполните:

```powershell
.\Start-Staging.ps1
```

Скрипт сначала запускает PostgreSQL, затем применяет миграции и только после этого запускает приложение.

## Безопасность сети

- PostgreSQL опубликован только на `127.0.0.1:5432`.
- Приложение опубликовано только на `127.0.0.1:8080`.
- Не создавайте проброс порта `5432` на роутере и не открывайте его в Windows Firewall.
- Для доступа сотрудников извне позже подключается HTTPS reverse proxy или VPN. Наружу публикуется только приложение, не база.

## Резервное копирование

```powershell
.\Backup-Database.ps1
```

Дамп создаётся в `backups/`. Копии этой папки нужно регулярно сохранять ещё на другом физическом диске или в закрытом облачном хранилище. Один диск компьютера не считается резервной копией.

## Проверка

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/v2/health/live
Invoke-RestMethod http://127.0.0.1:8080/api/v2/health/ready
```

Ожидаемый `ready`: база настроена и доступна. Начальные остатки сырья можно загружать как предварительные; подтверждёнными они становятся только после инвентаризации с сохранением отдельной складской операции корректировки.
