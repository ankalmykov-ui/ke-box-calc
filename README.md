# KE | BOX CALC — v0.7

**Интегрированная рабочая версия по согласованному функциональному ТЗ v1.0.**

## Модули v0.7

1. Листовая заготовка и FEFCO 0201.
2. Геометрия FEFCO 0201 по source-priority методике: отдельные L1/B1/L2/B2, рилёвки, стык изготовителя, caliper override.
3. Группа заказов и горизонт 1–3 дня.
4. Сырьё: ручной импорт XLSX/CSV из 1С, ключ Код 1С + Характеристика, история цены/остатка.
5. Утверждённые 3- и 5-слойные композиции.
6. Марки картона и отдельный нормативный справочник.
7. Лаборатория: XLSX/CSV preview/apply, нормализация, история ECT/BCT, агрегированная статистика.
8. Расчёт расхода и стоимости сырья с коэффициентами гофрирования.
9. Оптимизатор гофроагрегата: рабочая ширина, фактические рулоны, ручьи, краевая обрезь, перепроизводство, два уровня поперечной резки.
10. Переработка: P660 / 2Print / SRPACK — техническая применимость, форматная скорость, приладка, выбор машины.
11. Сквозной расчёт `/api/calc/full`: изделие → заготовка → раскрой → композиция → переработка → стоимость.
12. Сохранение заказа и снимка расчёта в PostgreSQL.

## Статусы, которые специально НЕ скрыты

- 2Print: паспорт не найден, часть ограничений остаётся рабочей/проверяемой.
- Скоростные зависимости перерабатывающих линий в v0.7 реализованы как редактируемая эвристическая модель; её нужно калибровать фактом.
- Полная стоимость переработки требует тарифов ₽/машино-час. Без них модуль показывает время, но не выдумывает стоимость.
- Исторический файл заказов используется только как диагностика, не как норматив.

## Запуск

```bash
cp .env.example .env
docker compose up --build
```

Открыть: `http://localhost:8000`

Проверка модулей: `GET /api/modules`

Тесты:

```bash
cd backend
pytest -q
```


## v0.7 — ввод изделий

Рабочий экран заказа имеет два равноправных входа:
1. ручное добавление изделий по одной позиции;
2. загрузка XLSX/CSV по шаблону с предпросмотром, валидацией и исправлением строк до принятия в заказ.

Шаблон: `GET /api/reference/order-template`. Предпросмотр: `POST /api/import/orders/preview`. Повторная проверка исправленных строк: `POST /api/import/orders/validate`.
