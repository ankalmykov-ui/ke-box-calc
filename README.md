# KE | BOX CALC v2.0

Новая реализация KE | BOX CALC по техническому заданию v2.2 от 27.08.2026.

Эта ветка создана с нуля и не является продолжением кодовой базы v0.7–v0.9. Архитектурная фиксация этапа 1 завершена. Технический каркас этапа 2 развёрнут. Запуск №1 добавляет настоящий PostgreSQL-контур сырья и первый ограниченный вариант FEFCO 0201: геометрию, расход сырья, обрезь и стоимость. BCT остаётся явно неподтверждённым до подключения утверждённых композиций и лабораторных данных.

## Источник истины

- «KE | BOX CALC — техническое задание v2.2» в Google Drive проекта;
- утверждённые формулы и версионируемые справочники;
- проверенные производственные параметры;
- паспортные данные оборудования;
- исторические техкарты — только как контрольные примеры.

## Неприкосновенные границы

- `main` и production v0.7.1 не изменяются;
- `v0.8-dev` и `v0.9-dev` сохраняются как история предыдущих подходов;
- разработка v2.0 ведётся в независимой ветке `v2-dev`;
- staging v2.0 использует отдельную базу и не имеет доступа на запись в production;
- перенос старого кода возможен только как отдельная проверенная реализация нового контракта, а не копированием старой архитектуры.

## Локальная проверка

После настройки локального окружения или отдельного staging в Yandex Cloud:

```bash
uv sync --dev
uv run ruff check .
uv run pytest
uv run uvicorn ke_box_calc.main:app --reload
```

Миграции выполняются отдельной командой и никогда не запускаются автоматически при старте контейнера:

```bash
uv run python -m ke_box_calc.db.migrator status
uv run python -m ke_box_calc.db.migrator up
```

## Docker и Yandex Cloud

v2 поставляется как переносимый Docker-образ и не зависит от Vercel. Инструкция по изолированному staging находится в [deploy/yandex-cloud/README.md](deploy/yandex-cloud/README.md).

```bash
docker build --tag ke-box-calc-v2:local .
docker run --rm --publish 8080:8080 --env DATABASE_REQUIRED=false ke-box-calc-v2:local
```
